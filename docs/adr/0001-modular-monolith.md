# ADR-0001：采用模块化单体而非微服务

状态：部分被 ADR-0006 取代  
日期：2026-07-11（2026-10-06 修订）

## 背景

CityCopilot 是本地生活交易后端，当前部署规模以单实例为主，团队规模不足以抵消服务拆分带来的发布、观测、数据一致性和联调成本。

## 决策

保持 Maven 多模块，依赖方向固定为 `core -> http-support/contracts`、`commerce-service -> http-support/contracts`，模块之间不允许反向依赖。只有交易写入所有权需要独立事务、独立扩缩容和故障隔离时才拆出独立进程，目前只有 Commerce 满足这个条件，见 ADR-0006。

## 结果

- 用户、店铺、社区、GEO 等低一致性要求的能力留在 Core 一个进程内，共享权限和审计语义。
- 交易写入集中在 Commerce，Core 通过版本化 HTTP 调用它；Commerce 不可用时 Core 失败关闭，不回退本地写入。
- 不按 Controller 数量或技术层拆服务；拆分需要真实的一致性或扩缩容理由。

## 面试回答

“我没有为了技术栈数量拆微服务。先用模块化单体固定依赖方向，只把真正需要独立事务和扩缩容的交易域拆成 Commerce 服务，其余能力留在 Core。”
