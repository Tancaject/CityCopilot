# ADR-0001：采用模块化单体而非微服务

状态：已被 ADR-0004 取代  
日期：2026-07-11

## 背景

CityCopilot 同时包含本地生活交易、Agent 编排、MCP 适配和离线评测。当前部署规模以单实例为主，团队规模不足以抵消服务拆分带来的发布、观测、数据一致性和联调成本。

## 决策

保持 Maven 多模块单体，依赖方向固定为 `mcp-server -> agent -> core`、`eval -> agent`。模块通过 Java 接口和 ToolGateway 形成边界，并用 ArchUnit 在 CI 中阻止反向依赖。

## 结果

- 交易与 Agent 仍能在一个进程内共享事务、权限和审计语义。
- 模块可以独立测试，未来出现独立扩缩容或故障隔离需求时再沿现有边界拆分。
- 不获得微服务级独立发布和故障隔离；这是当前流量和团队约束下的主动取舍。

## 面试回答

“我没有为了技术栈数量拆微服务。先用模块化单体固定依赖方向和业务边界，用 ArchUnit 防回退；只有当独立扩缩容、部署节奏或故障域成为真实问题时，才沿现有模块边界拆服务。”

2026-07-22 起，独立扩缩容、Agent 故障隔离和独立发布已成为项目演进目标，后续决策见 ADR-0004。
