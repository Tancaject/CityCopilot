# ADR-0003：高风险 Agent 操作必须人在回路

状态：接受  
日期：2026-07-11

## 背景

LLM 和 Critic 都可能误判。仅用另一个模型审批下单、支付、退款等写操作，无法把最终责任交给真实用户，也无法防止重复点击。

## 决策

Critic 只做确认卡生成前的预审。预审通过后，执行器暂停并创建绑定 `userId + traceId` 的一次性 `pendingId`，Redis TTL 为五分钟。只有同一用户调用确认接口后，操作才经 ToolGateway 执行；消费使用原子 get-and-delete，重复确认和跨用户确认均拒绝。

## 结果

- 写操作由用户明确授权，模型不再自我批准。
- 确认步骤进入 trace，便于审计和复盘。
- 交互多一步，pending 状态需要 Redis；这是降低错误写入风险的合理成本。

## 面试回答

“Critic 仍是 LLM，不能成为最终责任主体。我让它负责预审，让用户负责授权，再用一次性 pendingId 解决重放和重复点击，最终执行仍统一经过权限、校验、审计和熔断网关。”
