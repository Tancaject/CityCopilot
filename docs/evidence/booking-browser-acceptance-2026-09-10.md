# 双场景预约浏览器验收

2026-09-10 在本机浏览器实际操作 Vue 页面，并读取 MySQL 核对结果。使用独立测试 MySQL（`127.0.0.1:33319`）、Core 的 `citycopilot_booking_core_test` 和 Commerce 的 `citycopilot_booking_ui_test`；数据目录在仓库 `.tools/booking-mysql/data`。所有账号、商家、预约均为验收构造数据，不涉及真实商户或支付。

前端通过 Core HTTP 访问 Commerce；Core、Commerce 使用独立 JVM。页面确认由真实点击提交，没有通过修改数据库替代页面动作。测试账号为商家 `900`、用户 `100000`，店铺为 `90001`（预约验收运动馆）与 `90002`（预约验收餐厅）；不保存登录令牌或核销凭证。

## 实际页面操作

| 路径 | 操作与观察 |
| --- | --- |
| 商家发布 | 商家登录后台，发布羽毛球场、当地整点一小时时段、容量 1 的排期及 200 元场地价，发布满减规则。后台展示场馆与餐厅的不同容量含义。补充场地、套餐、纯订位及临近核销窗口的数据通过同一组商家 HTTP API 创建。 |
| 场馆领券与报价 | 用户登录店铺预约页，选择四人场地、日期和时段，领取三类券。页面显示最优组合为满减 30 元和代金 40 元，200 元场地最终为 130 元；优惠明细可见。 |
| 场馆暂留与确认 | 页面分别执行暂留和最终确认，显示占位截止时间。一个自然到期的暂留显示 HOLD_EXPIRED 并释放容量；重新暂留并确认成功。 |
| 场馆原子改期 | 从 9 月 11 日 18:00 改到同场地 19:00，页面核对旧、新时段与金额后提交；新预约详情为 19:00，130 元承诺保留。SQL 核对旧时段占用为 0、新时段为 1。 |
| 餐厅套餐预约 | 用户选择当日接待池、四人、每人 50 元套餐，页面显示总额 200 元及服务包含项、另付项；分别暂留和确认成功。 |
| 餐厅到店核销 | 切换商家登录，查到上述预约，输入用户凭证，核对四人预约并点击最终核销。页面显示“预约已核销；消费金额按预约约定线下结算”；明确此操作不表示支付渠道到账。 |
| 纯订位确认卡 | 以测试商家自己的普通预约身份，通过公开 API 生成 ON_SITE 报价和 HOLD 提案；打开确认卡只读取状态，显示“消费金额到店确定”。浏览器先点击“批准暂留名额”，再打开独立 CONFIRM 提案并点击“批准最终确认预约”，最终显示已确认与查询当前预约的链接。 |

纯订位的提案来自确定性 API，未经过模型生成。确认卡页面与批准入口已于 2026-10-06 随 Agent 一并移除。场馆浏览器预约为次日场次，本次未在页面核销该未来预约；场馆核销与旧凭证失效另由[真实 MySQL 生命周期验收](booking-delivery-evidence.md)覆盖。

## 数据库核对结果

以下是页面操作后的实际数据库快照，不代表当前部署状态。金额单位为分，时区为 Asia/Shanghai。

| bookingId | 用户 | 资源 / 时段 | 人数 / units | 状态 | version / scheduleVersion | 报价 |
| --- | ---: | --- | --- | --- | --- | --- |
| `3b9205e0-84a0-4230-9381-730114419195` | 100000 | 1 / 1 | 4 / 1 | HOLD_EXPIRED | 1 / 0 | FIXED 13000 |
| `483b1e8c-a046-4819-975b-7acfb53aaccc` | 100000 | 1 / 2 | 4 / 1 | CONFIRMED | 2 / 2 | FIXED 13000 |
| `59ec9aa5-4782-4388-a828-2be20d2b70f5` | 100000 | 5 / 14 | 4 / 4 | USED | 2 / 1 | FIXED 20000 |
| `b3b6b3ab-0e7a-4d6f-a80f-b54a6028792c` | 900 | 4 / 11 | 2 / 2 | CONFIRMED | 1 / 1 | ON_SITE null |

时段 1、2、11、14 的 `occupied` 分别为 0、1、2、4，均与仍占用资源的预约 units 之和相等。两张优惠券仍绑定已改期场馆预约，折扣券 AVAILABLE；没有因旧暂留到期或改期重复占券。已核销餐厅保留历史四人使用事实，不将 USED 的容量计数清零。

真实 RocketMQ 消费后的 Core 投影已核对场馆 CONFIRMED v2 和餐厅 USED v2。餐厅的 HELD v0、CONFIRMED v1、USED v2 三条事实均来自 COMMERCE；这些普通页面预约没有方案曝光，`attributed=false`，没有伪造为推荐转化。独立的曝光归因、消息集合及乱序验证见 [HTTP 与 MQ 验收](booking-api-acceptance-2026-09-10.md)。
