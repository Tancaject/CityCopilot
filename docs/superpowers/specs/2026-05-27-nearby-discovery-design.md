# 附近混合发现改造设计

## 目标

把店铺列表从“只展示数据库里已有的固定店铺”改造成“本地已入驻店铺 + 高德周边 POI”的混合发现能力。用户切换定位后，推荐结果必须跟着位置变化；当本地库附近没有店铺时，也能用高德周边地点补齐。

## 范围

- 新增统一发现接口 `/shop/discovery`。
- 保留 `/shop/nearby`、`/shop/of/type`、`/shop/of/name` 作为兼容入口；坐标查询委托当前本地发现 Provider，不再保留独立旧查询链。
- 不把高德 POI 自动写入 `tb_shop`。
- 前端店铺列表改用统一发现接口，并区分“已入驻店铺”和“附近地点”。

## 架构

后端新增一个发现层：

- 本地 Provider：有坐标时先用 Redis GEO 查附近店铺 ID，再由 MySQL 回表确认 `verified` 状态、类型和关键词并补齐详情；无坐标时使用普通 MySQL 分页。
- 高德 Provider：调用高德周边搜索接口，按当前位置、类型或关键词返回 POI。
- 聚合 Service：合并两路结果、去重、排序、分页，并输出统一 DTO。
- Controller：只暴露统一 API，不让前端关心数据源差异。

## 数据语义

统一返回项包含：

- `source`：`local` 或 `amap`。
- `orderable`：本地店铺为 `true`，高德 POI 为 `false`。
- `id`：仅本地店铺有真实店铺 ID。
- `sourceId`：外部来源 ID，本地可复用店铺 ID，高德使用 POI ID。
- `distance`：距离当前位置的米数。

## 排序与去重

- 以距离为主排序。
- 同一距离段内，本地店铺优先。
- 关键词搜索时，本地和高德都参与。
- 优先用 `poiId` 去重；没有 `poiId` 时，用名称、地址和坐标近似去重。

## 失败策略

- 高德 Key 缺失或高德调用失败时，只返回本地店铺。
- Redis GEO 未就绪或查询失败时，本地 Provider 使用 MySQL 包围盒 + Haversine 距离计算降级，不会只剩高德外部地点。
- Redis GEO 健康且查询为空时信任空结果，避免把正常的“附近无本地店”误判为故障。
- 本地无数据时，高德结果仍可展示。
- 坐标非法时返回明确错误。
- 高德周边结果使用已有 Redis 缓存机制，避免重复调用外部接口。

## 验收标准

- 不同定位返回的结果不同。
- 本地库附近没有店铺时，高德 POI 可以补齐。
- 高德 POI 不会写入 `tb_shop`。
- 关键词搜索也能结合当前位置。
- 高德异常时页面不白屏，后端不返回 502。
